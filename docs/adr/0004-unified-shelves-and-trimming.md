# 0004: Shelfに整理を統一し、視覚的にCellの区間を選ぶ

更新: [ADR 0005](0005-local-only-contact-and-public-previews.md)により、取得可能な公開動画の一時プレビューと12枚の実映像の場面帯に対応しました。以下の8枚・外部動画を取得しないという記述は当初の実装範囲です。

2026-10-09。ユーザーは動画追加時のShelf指定、あとからの柔軟な編集、Shelfとコレクションの区別をなくすこと、iPhoneのような切り取り操作、リンク動画の切り取りを明示的に求めた。この要求を仕様書のShelf/Collectionの区別より優先する。

画面の整理先をShelfに統一する。新規作成はShelfを使い、既存Collectionは同じ一覧で扱う。保存済みの名前・色・所属は変更せず、APIとデータモデルのCollectionは互換性のため残す。Shelfには動画とCellの両方を所属させるmany-to-many表を追加する。追加時の選択は所有権を検証し、Media作成と同じトランザクションで所属を保存する。保存済みリンクを別のShelfに追加してもMediaは複製しない。新規Cellは元動画のShelf所属を引き継ぎ、保存後はCell自身の所属を独立して変更できる。

MANAGEDのCellは、映像サムネイルの帯の両端を動かして区間を選ぶ。キーボードの矢印、Shift＋矢印、Home/Endも使える。細かい時刻入力は折りたたむ。サムネイルはブラウザ内で最大8枚だけ取り、保存せず、動画や編集画面を閉じると読み込みを止める。最大5分の区間、1動画100件・全体2,000件という上限は維持する。書き出しは要求時に行い、Cell作成時に動画ファイルを複製しない。

REFERENCEにも時刻付きCellを保存できるようにする。未知の動画長は推定せず、TikTokでは公式プレーヤーから動画長を取得するまで範囲選択と保存を待つ。その他の未知の動画長は最大60分内・1件5分までの区間の目印として扱う。リンクの表示では単一カバーを使い、実映像の場面サムネイルとは区別する。

- YouTubeは公式Iframe Player APIのstartSeconds/endSeconds、seekTo、pauseVideoと時刻取得で区間を制御する。キーフレームによる開始位置のずれがあり、フレーム単位の精度は保証しない。
- TikTokは公式プレーヤーのseekTo/play/pauseとonCurrentTimeを使う。受信元OriginとiframeのWindow、メッセージ型、有限の時刻と動画長を検証する。
- X/Instagramにはここで利用できる公式の区間再生制御がないため、Cellの区間は保存できるが、指定区間の再生は案内しない。

MP4書き出し・人物探索には動画ファイルが必要。保存済みリンクに元動画を追加するmultipart `reference_id` を設け、同じMediaをMANAGEDにする。タイトル・メモ・タグ・カバー・Source URL・Cell・所属は保持する。保存済みCellより短いファイルは取り込み前に拒否する。外部サービスからの動画取得、ログイン情報の取得、認証やDRMの回避は行わない。

根拠: [YouTubeのプレーヤーパラメータ](https://developers.google.com/youtube/player_parameters)、[TikTok Embed Player](https://developers.tiktok.com/docs/en/embed-player)。ローカルの動画書き出し精度と外部プレーヤーの区間確認精度は同一とは扱わない。

## 保存したCellの再生と一括整理

追加要求により、保存したCellは元動画の詳細へ遷移せず専用画面で開く。再生位置はCell先頭を0秒とし、最後まで再生しても範囲制限を解除しない。ローカル動画の標準コントロールを独自の区間内コントロールへ置き換え、再生・シーク・再再生のすべてで境界を適用する。元動画は明示的な別ボタンで開く。元ファイルを削除・複製せず、物理的な短いファイルが必要なときだけ既存のMP4書き出しを使う。

TikTokはユーザー操作でCellを開いた後に公式プレーヤーを読み込む。自動再生が制限される場合はプレーヤー内の操作を案内する。時刻通知の間隔を補う停止タイマーを持ち、区間終端でpause/seekToする。取得した動画長より長い保存済みCellは勝手に変更せず、編集時に有効な範囲を選び直す。YouTube APIはCellを開いた時だけ読み込み、既存のCSPを緩めない。外部サービスのおすすめ表示や利用制限を迂回しない。

ライブラリの動画グリッド・リストとCell一覧で複数選択を使う。表示中の全選択、解除、一括Shelf追加、新規Shelf作成に対応し、一度に100件まで。APIは全項目の所有権を確認してから一つのトランザクションで所属を追加する。再送時に重複を増やさず、一部失敗で所属を中途半端に変えない。

## 場面確認・範囲選択・Shelfの外観

TikTokの通常視聴中に動画長確認用のpauseが繰り返され、途中でおすすめ表示になっていた。通常再生・場面確認・区間試聴を共通プレーヤーで扱い、動画長は再生通知から読む。通常再生と場面確認に終了境界を設定せず、区間試聴だけ停止タイマーを使う。編集を閉じた後に境界を残さない。保存済みCell専用プレーヤーの範囲制限は維持する。

リンクの単一カバーを繰り返す帯は廃止し、時刻目盛りと再生位置を表示する。黄色い両端を動かすと公式プレーヤーがその場面へ移動し、「開始の場面を確認」「終了の場面を確認」「区間を再生」を使える。動画と編集欄はデスクトップで隣に、小さい画面で上下に配置する。急な連続操作は120msまとめ、最後の移動位置を送る。外部iframeの画素を抽出せず、外部動画ファイルを取得しない。おすすめ表示そのものの抑止は約束しない。TikTokの `rel=0` は関連動画を同じ投稿者に限定する設定で、非表示設定ではない。[公式Embed Player](https://developers.tiktok.com/docs/en/embed-player)。

Shift選択は画面の表示順で直前の選択位置と現在位置の間を追加する。直前の操作が解除なら同じ範囲を解除する。表示中の全選択と通常クリックも維持する。一括削除は名前・種類と関連Cell削除の説明を確認画面に出し、全件の所有権とJobを先に検証して原子的に処理する。1回100件まで。Cellだけの削除で元動画は消さない。

Shelfの名前・説明・色に加え、私的なヘッダー画像を編集できる。現代の写真を選べるよう入力を50 MiBに広げるが、保存時は1600×900px以内のJPEGへ縮小する。復号の画素・寸法・同時数を制限し、メタデータを保存しない。既存Collectionも同じAPIと画面に対応する。設定とユーザー情報は右上のアイコンに集約し、左のナビゲーションはライブラリと整理先に使う。
