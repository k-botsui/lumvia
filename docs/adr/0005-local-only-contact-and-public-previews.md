# 0005: ローカル専用、お問い合わせ、公開動画の場面画像

2026-10-09。ユーザーは、ログイン不要の取得可能な公開動画を一時取得する方式を明示的に選択した。またアプリは自分だけがローカルで使うものとし、データ共有を行わず、後日のGitHubお問い合わせだけ適切に接続するよう求めた。旧ADR 0002/0004の「外部動画ファイルを取得しない」という範囲を、一時プレビューに限って更新する。共有・クラウド化の計画は採用しない。

## ローカル専用

ネイティブ版のDB・動画・顔画像・秘密情報・ログ・バックアップはMacの `~/Library/Application Support/Lumvia/` に置き、Desktop/Documentsにあるコードの作業フォルダーから分離する。Linuxは `~/.local/share/lumvia/`。旧版は全サービス停止後、コピー先の素材とバックアップのSHA256を検証する。DBは論理dumpを新しいクラスタへ復元し、全テーブルの件数を照合する。iCloud管理下のクラスタ/キューの直接移動で停止することを避ける。元データはコピーと動作確認中に残し、復元検証後に旧保存先を片付ける。OS側で過去に同期されたコピーをアプリから削除することはできない。

起動スクリプトとWebの既定は127.0.0.1にバインド。設定検証でもAPP_URLをループバックだけ、永続ストレージをlocalだけ、DB・キューをループバックまたは既知のDocker内部サービスだけに制限する。OIDCやS3を有効にした設定は起動時に拒否する。Dockerの公開ポートは127.0.0.1、DBネットワークは内部のみ。共有リンク、テレメトリー、利用者データのクラウド同期を追加しない。

お問い合わせは認証付きGETで、管理者が設定した `owner/repository` から固定GitHub窓口を返す。未設定はnull。サーバーからGitHubへ接続しない。問い合わせ文は入力内容だけを明示的にコピーし、窓口を開く操作でも本文やユーザー情報をURLへ含めない。投稿はGitHub画面で利用者が確認して行う。ログ・動画・写真・ライブラリJSON・認証情報を添付する仕組みは持たない。

## 一時映像

切り取り画面を開いた場合だけ、所有権とCSRFを検証して公開動画を取得する。yt-dlpの匿名抽出に使うHTTPを独自のHTTPS実装に置き換え、全メタデータ・映像・リダイレクトでドメイン許可、公開IP検証、DNSで得たIPへの固定接続、ホスト名を使うTLS検証を行う。任意URL・HTTP・Cookieインポート・プロキシ・外部JS実行・ログイン・DRM回避は許可しない。サイトが発行する匿名Cookieだけをプロセス内で使う。

単一の非ライブMP4のみ、10分・32 MiB以下。メタデータ4 MiB/応答・合計16 MiB・40リクエスト・最大3リダイレクト。HTTP65秒、全処理90秒、FFmpeg45秒、スレッド2。FFmpegはローカル入力のみ、最大4096px・16ストリームを検証し、640px以内のH.264/AACへ変換する。出力サイズと元動画との差100ms以内を検証し、途中までのプレビューを成功として返さない。実映像のタイムラインはブラウザーで12枚、拡大時に再生成する。

ファイルロックで全体同時1件、取得8回/所有者/時。原本と変換中ファイルを含めて256 MiB以内に収めるため事前に容量を予約し、古いキャッシュを回収する。キャッシュは30分で失効し、Workerが閉じた画面のデータも回収する。永続AssetやMediaを増やさず、通常のバックアップからも分離する。配信は所有権が必要、Range対応、no-store。保存したCellはキャッシュがある間はその映像から区間専用プレーヤーで再生し、失効後は公式プレーヤーを使う。

取得不可は日本語で説明し、元動画ファイル追加を残す。すべての公開投稿・配信形式の取得を保証しない。外部サービスへのリンク機能は接続先にIP等が伝わるため、完全オフラインの機能とは扱わない。自分のアップロード動画と人物解析を外部へ送らない。
